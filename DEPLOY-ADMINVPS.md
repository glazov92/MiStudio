# 🚀 Развёртывание сайта MiStudio на AdminVPS (тариф Promo)

Виртуальный хостинг AdminVPS (тариф **Promo**): 5 ГБ NVMe, 2 сайта,
панель **ispmanager**, PHP + MySQL, бесплатный SSL, ежедневные бэкапы,
7 дней тест-драйва. Этого с запасом хватает для сайта-визитки салона.

В результате вы получите:
- сайт на вашем домене (HTTP + HTTPS);
- **админку `?edit=sLQSSJCRpwRrsdYSNhQR`, которая сохраняет правки на сервер** — изменения видны
  всем посетителям с любого устройства (через `content-sync.php`).

<a name="заказ"></a>
## 1. 🛒 Заказ хостинга

1. Откройте https://adminvps.ru/host/hosting_russia.php — тариф **Promo** (199 ₽/мес).
2. Зарегистрируйтесь / войдите в личный кабинет (https://my.adminvps.ru).
3. Оформите хостинг Promo. Совет: при оплате на год — домен в подарок и скидка;
   если не уверены — оплатите 1 месяц, есть **7 дней тест-драйва**.
4. После оплаты в кабинете появится доступ в панель **ispmanager** (адрес вида
   `https://хостинг.adminvps.ru:1500`), логин/пароль и IP сервера.

> Напишите в техподдержку через тикет-систему кабинета — бесплатно помогут
> привязать домен, выдать SSL и загрузить файлы, если что-то пойдёт не так.

<a name="панель"></a>
## 2. 🖥️ Создание сайта в панели ispmanager

1. Войдите в панель ispmanager (данные придут на почту после заказа).
2. Раздел **Сайты → Добавить сайт**.
3. Укажите ваш домен (например `mistudio.ru`) — без `www`, панель сама предложит
   добавить и вариант с `www`.
4. Запомните **путь к файлам сайта** (документ-рут) — обычно
   `public_html` внутри папки сайта.
5. Если в списке предлагаются PHP/MySQL — выберите **PHP 8.x** (или 7.4), база не
   нужна (сайт хранит правки в JSON-файле).
6. Сохраните. Сайт создан.

<a name="домен"></a>
## 3. 🌍 Домен и DNS

**Вариант А — домен куплен в AdminVPS:** ничего настраивать не нужно —
DNS пропишутся автоматически.

**Вариант Б — домен у другого регистратора** (например reg.ru, nic.ru):

1. В кабинете AdminVPS/панели найдите **IP-адрес** вашего хостинга.
2. У регистратора, где куплен домен, откройте **DNS-записи** (или делегирование).
3. Добавьте **A-запись**:
   ```
   @         A   <IP хостинга>
   www       A   <IP хостинга>
   ```
   (Если есть старые A-записи — замените их, не добавляйте вторые.)
4. DNS обновляется от 15 минут до 24 часов.

<a name="файлы"></a>
## 4. 📁 Загрузка файлов сайта

В панели откройте **Файловый менеджер** (или подключитесь по **FTP/SFTP** —
доступы есть в разделе «FTP-пользователи»).

Зайдите в **документ-рут сайта** (`public_html` — папка из шага 2.4) и загрузите
всё содержимое проекта `C:\Users\user\Desktop\MiStudio`:

```
public_html/
├── index.html          ← лендинг (единственная страница, все секции на ней)
├── config.js           ← конфигурация (телефоны, вебхук, ключ админки)
├── content-sync.php    ← PHP-скрипт синхронизации правок админки
├── css/                ← стили (style.css, editor.css)
├── js/                 ← скрипты (main.js, data.js, editor.js, storage.js, sections/)
├── img/                ← фотографии
└── data/               ← папка для хранения правок (создаст сама PHP-скрипт,
                         но .htaccess из проекта в неё положите)
```

> Не забывайте `data/.htaccess` — он запрещает прямое скачивание файла с правками.
> Файл правок `data/editor-store.json` появится автоматически после первого
> сохранения в админке.

> ⚠️ **Не загружайте лишнего**: папку `.git`, файлы `_*.txt`, `webhook/` и сам
> `.htaccess` из корня проекта. Корневой `.htaccess` нужен (см. шаг 6 — HTTPS и
> заголовки), а вот `.git` (служебная папка разработки) на хостинг не нужен
> вообще — он откроет доступ к исходникам.

<a name="ssl"></a>
## 6. 🔒 SSL-сертификат (HTTPS)

1. В панели: **Сайты → ваш сайт → SSL-сертификат**.
2. Выберите **Let's Encrypt** (бесплатно) → выдать для домена и `www`.
3. Включите принудительное перенаправление на HTTPS, если панель предлагает.
4. Через пару минут сайт откроется по `https://`.
5. В корень сайта должен лежать `.htaccess` из проекта — он добавит заголовок
   **HSTS** (браузер будет ходить только по HTTPS и отклонять поддельные
   сертификаты), защитные заголовки, запрет листинга папок и закрытие `.git`/
   служебных файлов. Если файл не загрузился — загрузите его вручную.

> **Про «подмену SSL»:** сайт работает по HTTPS с валидным сертификатом
> Let's Encrypt — это и есть защита канала. HSTS из `.htaccess` страхует
> вдвойне: даже если кто-то в той же сети попытается «подменить» соединение
> на http:// или подсунуть чужой сертификат — браузер сам уйдёт на https://
> и покажет предупреждение. Это работает автоматически после шагов выше.

<a name="ключ"></a>
## 7. 🔑 Ключ синхронизации админки

Ключ хранится в двух местах и должен совпадать:

| Где | Что |
| --- | --- |
| `config.js` → `EDITOR_CONFIG.serverSync.key` | ключ, который шлёт браузер |
| `content-sync.php` → `CMS_KEY` | ключ, который проверяет сервер |

По умолчанию там был `xlfQKw6pD1h1cHwfaVwaxaCq`. Перед загрузкой на хостинг
**замените на свой** (например, случайную фразу) в обоих файлах. Поменяли — залейте
заново оба файла.

> ✅ **Сделано при деплое (19.08.2026):** ключ заменён на отдельный сгенерированный
> (`S9x9Veh0hnHB4liskfCujugz`). Старый ключ сервер отклоняет (403). Если меняете
> ещё раз — обновите оба файла и залейте заново.

> В `config.js` ключ хранится **в замаскированном виде**, чтобы его нельзя было
> вытащить из исходников через Ctrl+F. Чтобы заменить, не пишите ключ открытым
> текстом — закодируйте перевёрнутую строку в base64:
> `base64("свой-ключ" перевёрнутый)` → подставьте в `editorUnlock('…')`
> в `config.js`. В `content-sync.php` ключ остаётся обычным текстом (он на
> сервере, в браузер не попадает).

> Ключ всё равно достижим через F12, поэтому это не защита от взлома, а защита
> от случайной перезаписи (как и `?edit=…`). Полную защиту даёт только серверный
> вход. Достаточно для текущей задачи.

<a name="проверка"></a>
## 8. ✅ Проверка работы

1. Откройте сайт: `https://ваш-домен/` — должен отрисоваться лендинг
   со всеми секциями (акции, услуги, о нас, портфолио, контакты).
2. Проверьте синхронизацию:
   - откройте `https://ваш-домен/content-sync.php` — в ответе `{}` или
     JSON с правками (не ошибка сервера и не «Access denied»);
   - зайдите в админку: `https://ваш-домен/?edit=sLQSSJCRpwRrsdYSNhQR`;
   - нажмите на любой текст → измените → **Сохранить**;
   - откройте сайт в **обычном (инкогнито) окне** — правка видна;
   - повторно откройте `content-sync.php` — там появилась ваша правка;
   - откройте `https://ваш-домен/content-sync.php?action=versions&key=КЛЮЧ`
     (КЛЮЧ = ключ из шага 7) — должен прийти JSON со списком версий `[{id, time}]`.
3. Проверьте HTTPS, телефон/ссылки, отправку заявки (форма → сообщение в
   беседу VK + письмо на почту).

<a name="бэкапы"></a>
## 9. 💾 Бэкапы и версии

Три независимых уровня защиты — используйте хотя бы первые два:

1. **Версии правок прямо в админке** (без хостинга не работают):
   кнопка **🕘 История** в панели `?edit=sLQSSJCRpwRrsdYSNhQR`. При каждом сохранении
   `content-sync.php` кладёт снапшот в `data/versions/` (последние 15,
   файлы до 1,5 МБ; папка защищена `.htaccess`). Любая версия откатывается
   кнопкой «↩️ Откатить», перед откатом текущее состояние тоже сохраняется —
   откат всегда можно отменить. Список версий: `?action=versions`, откат:
   `?action=restore` (оба — по ключу из шага 7).
2. **Бэкап правок на компьютер**: в панели админки **📤 Экспорт** → храните
   JSON у себя. Плюс после изменений скачивайте с сервера
   `data/editor-store.json` (через файловый менеджер/FTP).
3. **Бэкап всего сайта — встроенный модуль ispmanager**:
   - В панели: **Резервные копии → Настройки**. Если модуль входит в тариф,
     включите ежедневную/еженедельную копию (копируется `public_html` +
     файлы правок). Восстановление — тем же модулем.
   - Если модуля на тарифе Promo нет — раз в неделю скачивайте папку
     `public_html` целиком через файловый менеджер (архив через
     «Создать архив» в панели) и храните локально/в облаке.
   - Готовые `img/`, `css/`, `js/` и `index.html` всегда можно пересобрать из
     локального проекта — это ваш основной источник кода.

> Версии в админке хранят только правки контента (`data/`). Код сайта
> версионируйте в git (локально + GitHub) — хост держит только «прод».

## 10. 🗓️ Что делать дальше

- **Контент сайта** (тексты, картинки, акции, услуги, портфолио, ссылки)
  правьте в админке `?edit=sLQSSJCRpwRrsdYSNhQR` — изменения сразу видны всем.
- **Файлы сайта** (вёрстка, стили, скрипты) — меняйте в проекте и заливайте
  заново через файловый менеджер/FTP. Правки в `data/editor-store.json`
  при этом не теряются.
- **Бэкап правок** — в панели админки есть **🕘 История** (версии на сервере)
  и **📤 Экспорт** (JSON на компьютер). Раз в время жмите Экспорт и храните
  файл у себя (на сервере бэкапы хостинга тоже есть, но свои надёжнее).
- Обновляйте **кеш-версию** в HTML (`?v=...` в тегах скриптов), если меняли JS.

<a name="проблемы"></a>
## 11. 🆘 Частые проблемы

| Проблема | Решение |
| --- | --- |
| Сайт не открывается по домену | DNS ещё не обновился (до 24 ч); проверьте A-запись; попробуйте по IP |
| Картинки не грузятся | Не залита папка `img/` или неверный путь в `config.js`/данных |
| `content-sync.php` выдаёт 403/404 | Проверьте, что файл в документ-руте и называется точно `content-sync.php` |
| В админке «Сохранено локально (сервер недоступен)» | Проверьте адрес `content-sync.php` через браузер и ключ в `config.js`/PHP |
| При сохранении ошибка 500 | Дайте права на запись для папки `data/` (владелец = пользователь PHP, обычно уже так; при сбое — 775 через файловый менеджер) |
| PHP-скрипт не работает, версия PHP старая | Проверьте PHP-версию сайта (шаг 5) |
| При сохранении в админке ошибка 429 «slow down» | Значит, две записи отправлены быстрее, чем раз в секунду (защита от «молотка»). Просто подождите секунду и нажмите Сохранить ещё раз |

<a name="защита"></a>
## 12. 🛡️ Защита — что уже есть и чего не надо бояться

Всё, что сделано на этом сайте для защиты (по нарастающей):

| Защита | Где | От чего |
| --- | --- | --- |
| HTTPS + HSTS | SSL (шаг 6) + `.htaccess` | подмена SSL, перехват канала, поддельные сертификаты |
| HTTP→HTTPS (301) | `.htaccess` | понижение соединения до http:// |
| Защитные заголовки (`X-Frame-Options`, `nosniff`, `Referrer-Policy`) | `.htaccess` | кликджекинг, сниффинг MIME, утечка реферера |
| Листинг папок выключен + `.git`/служебные закрыты | `.htaccess` | просмотр структуры и исходников |
| `data/` закрыта `.htaccess` | `data/.htaccess` | прямое скачивание файла с правками |
| Ключ не в открытом виде | `config.js` | вытаскивание ключа через Ctrl+F/F12 |
| Проверка Origin + троттлинг записей (1/сек) | `content-sync.php` | чужие сайты шлют правки, перебор ключа, затирание данных |
| Версии правок (откат) | `data/versions/` | потеря/порча данных (не защита, но страховка) |

**Чего на сайте нет (и почему это не страшно):**
- Нет полноценной серверной авторизации админки — фронтенд-ключ виден через
  F12. Это осознанный выбор для такого сайта: правки контента — не
  «база данных с деньгами», а при полной защите пришлось бы вводить логин
  при каждом заходе. Уровня «дверь с защёлкой» достаточно.
- Нет CSP — из-за inline-скриптов редактора его нельзя включить без риска
  сломать админку. Если захотите усилить — сначала вынести inline-код в
  отдельный файл.
- VK/Telegram-токены **не** хранятся в репозитории (`webhook/` в `.gitignore`),
  на хостинг их заливать не нужно.

**Что делать владельцу, чтобы не потерять сайт:**
1. Хранить ключи админки только у себя (этот гайд — файл для доверенных людей).
2. Регулярно жмёте **Экспорт** в админке и храните JSON на компьютере.
3. Не открывать доступ к панели хостинга никому постороннему.
